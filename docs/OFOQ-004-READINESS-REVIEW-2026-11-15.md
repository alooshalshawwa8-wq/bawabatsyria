# OFOQ-004 — مراجعة الجاهزية الهندسية

**التاريخ:** 2026-11-15  
**النطاق:** مراجعة قراءة فقط لفرع التطوير `ofoq/ofoq-001-execution` ومشروع Supabase المرتبط.  
**المرجعية:** طلب التطوير #23، وملفات التدقيق السابقة.  
**القرار:** إبقاء التغييرات على فرع التطوير وعدم دمجها أو نشرها في الإنتاج ضمن هذه المراجعة.

## 1. نتيجة التحقق من GitHub

- المستودع الأساسي: `alooshalshawwa8-wq/bawabatsyria`.
- الفرع الإنتاجي: `main`.
- فرع التطوير: `ofoq/ofoq-001-execution`.
- رأس الفرع الذي تمت مراجعته: `3c971a6498db319614f0f4faf95a61a2027e2335`.
- طلب التطوير #23 ما زال مفتوحاً ومسودة.
- فحوص GitHub المرتبطة برأس الفرع اكتملت بنجاح: ثلاثة فحوص `validate` وفحص `Read-only application and security checks`.
- نجاح CI يثبت نجاح الفحوص الآلية التي شُغّلت على هذا الالتزام، ولا يثبت نجاح التسليم الفعلي للبريد أو تجربة مستخدم حقيقية في الإنتاج.

## 2. نتيجة Supabase الحالية

- Health Advisor: لا توجد ملاحظات.
- Security Advisor:
  - تحذير واحد من المستوى WARN: حماية كلمات المرور المسرّبة معطّلة.
  - 11 ملاحظة INFO لجداول عليها RLS دون سياسات. الجداول المرصودة: `ai_provider_daily_usage`, `football_api_budget_policy`, `football_api_budget_reservations`, `football_api_cache`, `football_api_rate_limits`, `football_api_usage`, `ofoq_revenue_events`, `platform_feature_catalog`, `platform_launch_config`, `platform_plan_catalog`, `platform_plan_features`.
  - لا تُنشأ سياسات عامة أو تُفتح صلاحيات هذه الجداول قبل تحديد المستهلكين الفعليين؛ قد تكون جداول داخلية خادمية ويكون المنع الحالي مقصوداً.
- Performance Advisor: 25 فهرساً غير مستخدم وفق الرصد الحالي. لا تُحذف الفهارس بناءً على هذا التنبيه وحده؛ يلزم قياس حمل واقعي ومراجعة خطط الاستعلامات.
- لم تُعدّل هذه المراجعة أي إعداد Auth أو RLS أو بيانات أو أسرار أو فهارس أو Edge Functions.

## 3. نقاط مراجعة فرع التطوير

- يتضمن الفرع اختبارات تعاقدية لوظائف Edge، واختبارات توقيع Stripe، واختبارات متصفح وهاتف، وفحصاً آلياً للكتالوج والأزرار والملفات المحلية.
- اختبارات Auth في المتصفح تستخدم محاكاة ولا تتصل بحسابات حقيقية؛ لا تعتبر دليلاً على وصول رسالة تأكيد إلى صندوق بريد فعلي.
- مصدر `site-assistant` في الفرع يتضمن حصة يومية محجوزة عبر قاعدة البيانات، وحدوداً لطول الرسائل ومعدل الطلبات.
- تغييرات Stripe في هذا الفرع ليست إذناً بتفعيل الدفع. تبقى بوابة الدفع مغلقة حتى اعتماد المتطلبات التجارية والقانونية والتشغيلية، وتوفير إعدادات مزود الدفع ومفاتيحه بموافقة المؤسس.
- لا توجد في هذه المراجعة عملية دمج أو نشر أو إعادة نشر لوظائف الإنتاج.

## 4. ما يزال مطلوباً قبل إطلاق التسجيل العام

1. إعداد SMTP موثّق بنطاق المشروع واختبار وصول البريد إلى صندوق بريد حقيقي.
2. تفعيل حماية كلمات المرور المسرّبة في إعدادات Supabase Auth، ثم إعادة تشغيل Security Advisor.
3. جرد الجداول الـ11 وتوثيق سبب كونها خادمية فقط، ثم مراجعة المنح والسياسات دون فتح الوصول افتراضياً.
4. مطابقة سجل migrations: التدقيق السابق رصد 36 ترحيلاً مطبقاً مقابل 22 ملفاً في المستودع؛ يجب استعادة/توثيق الملفات المفقودة قبل أي تغييرات مخطط مستقبلية.
5. إجراء دورة اختبار بحساب مخصص: التسجيل، التأكيد، الدخول، الخروج، الدخول مجدداً، واستعادة كلمة المرور.
6. اختبار عزل المستخدمين والنسخ الاحتياطي والاستعادة في بيئة معزولة.

## 5. القرار التنفيذي

- الاحتفاظ بالفرع وطلب #23 كمسودة للمراجعة النهائية.
- عدم دمج التغييرات إلى `main` أو نشرها قبل إغلاق متطلبات البريد الحقيقي ومراجعة الأمن والاختبارات.
- إبقاء `launch_mode=trial`, و`billing_enabled=false`, و`paid_features_enforced=false`.
- مواصلة أعمال التوثيق والاختبار الآمن على فروع التطوير فقط.
