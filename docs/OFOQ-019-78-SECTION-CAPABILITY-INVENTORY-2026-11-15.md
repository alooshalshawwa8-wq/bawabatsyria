- اختبار سلوك Escape لمركز الأوامر.
- اختبارات متخصصة لمسارات محددة: XSS في سجل التداول، واجهة استعادة كلمة المرور عبر Auth محاكى، مسودة محتوى اجتماعي والحفظ المحلي، عمليات Operations Hub، تصدير JSON، وفحوصات تجاوز العرض على الهاتف.

**حد الإثبات:** الاختبارات تثبت سلامة التنقل والإطار المشترك والمسارات المحددة فقط؛ ولا تثبت صحة جميع الحاسبات أو دقة المحتوى أو اتصال الأقسام بمصادر حية.

## 5. خريطة التكاملات الخارجية المثبتة من المصدر

| التكامل/النطاق | الدليل البرمجي | الحالة التي يمكن اعتمادها |
|---|---|---|
| Supabase Edge Functions | `site-assistant`, `membership-api`, `football-data` | الوظائف منشورة/نشطة حسب الجرد المباشر؛ مفاتيح المزودين لا تُعد مثبتة بمجرد وجود أسمائها. |
| Gemini | استدعاء من `site-assistant` إلى `generativelanguage.googleapis.com` | مسار تكامل موجود؛ توفر المفتاح والحصة والنجاح الفعلي لكل طلب يحتاج فحص تشغيل حي آمن. |
| Stripe | استدعاءات في `membership-api` وCloudflare Worker | الدفع معطل في إعداد المنصة؛ لا تسويق أو تحصيل مدفوعات. |
| API-Football | `football-data` و`API_FOOTBALL_KEY` | المزود محظور حالياً؛ لا بيانات كرة قدم حية. |

| متجر Supabase | مخطط سحابي للمنتجات والطلبات ومزامنة يدوية اختيارية | لا يوجد متجر عام أو دفع أو مزامنة تلقائية في الخلفية وفق المصفوفة الحالية. |

## 6. أسماء متغيرات البيئة/الأسرار التي رُصدت (الأسماء فقط)

- `site-assistant`: `GEMINI_API_KEY`, `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `SUPABASE_SECRET_KEYS`.
- `membership-api`: `PAYMENTS_ENABLED`, `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`, مفاتيح Supabase و`SITE_URL`.
- `football-data`: `API_FOOTBALL_KEY` ومفاتيح Supabase.
- Cloudflare Worker: `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`, `AUTH_ISSUER`, `AUTH_AUDIENCE`, `AUTH_JWKS_URL`, `POINTS_ADMIN_KEY`، وغيرها من إعدادات النطاق.

لم تُقرأ قيم الأسرار ولم تُنسخ أو تُكشف أو تُعدل. وجود اسم متغير لا يثبت أن قيمته مضبوطة.

## 7. أولويات الاستكمال

1. **P0 — بوابة إطلاق عامة:** SMTP والبريد الفعلي، موثوقية هوية العميل ومحدد إساءة الاستخدام الدائم، حماية كلمات المرور المسرّبة، عزل متعدد المستخدمين واستعادة النسخ الاحتياطية، موافقة الإطلاق.
2. **P1 — أقسام حساسة تجارياً:** المحاسبة والمخزون، التجارة الإلكترونية، الوظائف، دليل الخدمات، السوق، العقارات، الأسعار.
3. **P1 — أقسام بيانات خارجية:** كرة القدم، الأخبار، الأسعار، السفر، الفعاليات؛ لا تُعرض بيانات مباشرة قبل توصيل مصدر موثوق وفحص حداثته.
4. **P2 — الأقسام الـ18 العامة:** تصميم أداة تخصصية لكل قسم، مع اختبارات مدخلات ومخرجات وحالات فشل وبيان حدود الاستخدام.
5. **P2 — اختبارات قبول المجال:** اختبار فعلي لكل زر ومخرج رئيسي، وليس مجرد اختبار ظهور القسم.

## 8. ضوابط التنفيذ

- التطوير على فرع العمل فقط؛ لا دمج إلى `main` أو نشر.
- لا تغييرات على الإنتاج أو Auth أو SMTP أو RLS/GRANT أو DNS أو الأسرار.
- المجاني أولاً؛ لا شراء أو ترقية أو تفعيل خدمة مدفوعة.
- لا ادعاء بأن أداة محلية أو قالب هو خدمة AI حية.
- لا تخزين أو تسجيل قيم مفاتيح API في تقارير الجرد.
- يجب ربط كل حالة `LIVE_VERIFIED` باختبار حي آمن ومصدر ووقت آخر تحقق.

**الحالة:** جرد الأقسام الـ78 وتصنيفها الأولي مكتمل توثيقياً؛ اختبار الوظائف التخصصية لكل قسم ما زال backlog منفصلاً.
